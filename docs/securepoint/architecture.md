# Architecture

`cmd/sp-utm-mcp` loads TOML profiles, validates group names and schemas, and starts the SDK's stdio or Streamable HTTP server. Startup does not connect to appliances. `--version`, `--catalog`, and `--check` are offline CLI commands. The `[server].transport` setting defaults to stdio; `--transport` overrides it.

The HTTP adapter is a stateless, JSON-response MCP handler at `/mcp`, backed by the same engine used by stdio. A bearer token loaded from `server.http.token`, or the configured environment variable when that setting is empty, identifies one shared administration principal. Authentication is checked on every request. Explicit host validation, exact-origin checks/CORS preflight, bounded bodies/headers, and TLS for non-loopback binds protect the endpoint. Reverse proxies use the explicit host/origin allowlists; forwarded headers are not trusted. HTTP clients retain the same profile permissions, plan expiry/replay protection, and artifact ownership rules. Plans live in the process across HTTP requests, rather than in HTTP sessions. This is a single-principal service, not multi-user authorization.

`internal/securepoint/catalog` embeds finite operation definitions with revision provenance, parameter schemas, permission classification, activation dependencies, and precondition commands. Tool arguments never supply a free-form CLI or shell command. Input schemas are validated with JSON Schema; the command builder additionally enforces the CLI grammar and core semantic constraints.

`internal/securepoint/engine` is the sole path for appliance calls. Each profile has a cancellable semaphore, serializing reads and writes within this process. Capabilities are discovered through read-only `system info` and `help`, cached for one minute, and refreshed before execution. Firmware 14.x is required; inability to parse firmware disables operations other than system information. Help results describe advertised commands, not live verification.

A mutation call validates permissions, builds its request, reads relevant state, and checks documented references. It retains the original request and raw state hash in memory, returning a redacted preview. Execution rechecks firmware, state, references, and permissions. Plans are consumed before sending the first mutation; successful prefixes and failed/uncertain steps are reported separately. There are no retries or hidden rollback attempts.

Where a stable resource getter is unavailable, a configuration-list snapshot is used. This detects changes to the listed configuration state, not every possible external application change. Preview notes and the coverage report describe this limitation. External administrators can still race between the last read and a write.

`internal/securepoint/cli` encodes quoted scalars, recursive lists/objects, positional EXTC batches, and restricted multiline stdin. It parses pipe-delimited tables, paginates results, and redacts secret fields and private-key blocks before producing ordinary tool output.

`internal/securepoint/transport` opens a fresh verified SSH connection per request, with context-driven cancellation, bounded output, and no PTY. Administrator accounts receive CLI exec requests; root profiles invoke `spcli` using shell-quoted argv. With `json_output=true`, a root profile starts `spcli` and supplies the session-local `cli json` directive plus the encoded command on stdin. Complete JSON response codes are authoritative for the observed exit-255 legacy behavior; malformed/truncated responses never override failures. The single shell diagnostic is a fixed, bounded tcpdump invocation. SFTP is separately permissioned and restricted to the documented report directory and the dedicated staging directory.

`internal/securepoint/artifact` creates exclusive files under an `os.Root`, with random IDs, profile binding, content hashes, and 0600 permissions. Sensitive exports bypass ordinary output parsing and become local artifacts. Artifact reads recheck profile ownership and file integrity. Plan state, credentials, exported bytes, and raw appliance output are never audit log fields.

The documentation pipeline records the wiki inventory, caches source content outside Git, extracts rendered CLI tables, and applies explicit semantic corrections. Built-in help observed on 14.1.5 augments local interfaces and corrects parameter names. `tools/securepoint/finalize_catalog.py` is the review point for parameter, permission, and activation changes. Unavailable entries remain visible to clients with an explicit reason. A complete runtime command inventory can reject operations absent from that inventory; abbreviated or incomplete help cannot establish that a command is unavailable, so the appliance response remains authoritative in that case. SFTP upload staging is restricted to `/tmp/sp-utm-mcp`.

Go interfaces around SSH and file transfer allow deterministic tests. The test suite exercises real MCP clients over in-memory transports and real SSH framing/authentication against a local protocol fixture. Separately, the built executable passed 27 read operations over actual MCP stdio against firmware 14.1.5. This validates those read paths, without establishing write compatibility or complete support for other firmware revisions.
